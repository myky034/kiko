| DEC-015 | **Verified TLS for every remote database connection.** Supabase's pooler presents a certificate from Supabase's own CA (not in the system store), and `pg` uses no TLS by default. Runtime (`DATABASE_URL`, pg dialect): `sslmode=verify-full&sslrootcert=<CA path>`; Prisma CLI and operator scripts (`DIRECT_URL`, Prisma dialect): `sslmode=require&sslaccept=strict&sslcert=<CA path>`. Verified: Prisma with `sslmode=require` alone, or with `sslcert` but without `sslaccept=strict`, connected despite a wrong CA (no verification); with `sslaccept=strict` a wrong CA is rejected before authentication. The app, `prisma.config.ts` (for `migrate`/`db`) and both scripts refuse remote URLs without these parameters. Loopback hosts are exempt. | Derived | 2026-10-17 | `server/config/env.ts`, `prisma.config.ts`, `scripts/lib/db.mjs`; tests |
| DEC-016 | Migration `20261017000200_protect_migration_history` revokes the Supabase default grants on `public._prisma_migrations` from `anon`, `authenticated`, `service_role` and enables RLS, because `public` is exposed by the Data API and Supabase grants new `public` tables to those roles. | Derived | 2026-10-17 | Read-only review of `pg_default_acl` on the dev project; `tests/db`, `tests/integration` |
| DEC-017 | Runtime credential: `scripts/provision-runtime-role.mjs` generates the `kiko_app` password locally, sends only its SCRAM-SHA-256 verifier over verified TLS, checks the login through the transaction pooler and writes `DATABASE_URL` to `.env.local` (mode 600) without printing it. Re-running rotates the password. | Derived | 2026-10-17 | RFC 7677 vector test; local Postgres run |
| DEC-018 | **Authentication: Google OAuth through Supabase Auth (PKCE)**, replacing email OTP. Local origin `http://localhost:8080` (`npm run dev`/`start` default port 8080, `PORT` overrides). Callback `/auth/callback` exchanges the code and redirects only to allow-listed internal paths (`/`, `/onboarding`) on the configured `KIKO_APP_ORIGIN`, never on request `Host`/`X-Forwarded-Host`. The OAuth start follows the provider URL only if it is on the configured Supabase origin. Only sessions whose JWT `amr` contains `oauth` are accepted, so an email/password identity that Supabase auto-links by email cannot reuse an admitted account. Admission, account state and roles are unchanged. | Accepted (Google, port) / Derived (mechanics) | 2026-10-17 | Owner decision; `app/auth/callback/route.ts`, `modules/identity/*`; tests |
| DEC-019 | **Prisma CLI reaches Supabase through a loopback TLS tunnel** (`scripts/prisma-remote.mjs`, used by `db:migrate:status`/`db:migrate:deploy`). On macOS the Prisma CLI validates TLS with Apple's Security framework, which rejects Supabase's pooler certificate even with the Supabase CA (`security verify-cert -p ssl`: `OtherTrustValidityPeriod` — 1825-day validity — and `ServerAuthEKU`; the same chain passes basic X.509 validation and Node/OpenSSL). Instead of disabling verification, Prisma connects to `127.0.0.1:<ephemeral port>` and Node relays over TLS verified against the Supabase CA and host name; a wrong CA or host is refused before any bytes are relayed. Runtime and operator scripts use `pg` (OpenSSL) directly and are unaffected. | Derived | 2026-10-17 | Read-only `migrate status` through the tunnel; wrong-CA control; `tests/unit/tls-tunnel.test.ts` |

## Open decisions

| ID | Question | Notes |
|---|---|---|
| OPEN-001 | Language scope vs design brief | `DESIGN_SYSTEM.md` mentions Korean and French; the repository scope is zh/ja/en. No language added or removed. |
| OPEN-002 | Supabase sign-up and other providers | "Allow new users to sign up" must stay enabled so an approved Google account can be created at first sign-in; Kiko access is still denied without admission. Recommended: disable the **Email** provider (and phone/anonymous) so only Google identities exist; the server also rejects non-OAuth sessions (DEC-018). |
| OPEN-003 | Database TLS rollout | Enforced in code (DEC-015, DEC-019); the operator machine has the Supabase CA. **Enforce SSL is still off** on the dev project: a no-password probe on 2026-10-17 showed the pooler (5432, 6543) and the direct host accept plaintext sessions. Earlier read-only probes ran without TLS; authentication used SCRAM-SHA-256, so the password itself was not sent, but query traffic was unencrypted and a captured SCRAM exchange allows offline guessing. Enable Enforce SSL and rotate the `postgres` password (KHLOE-203). |
| OPEN-004 | Owner administration UI | Admission/suspension via `scripts/kiko-admin.mjs` only. Role changes for existing accounts and last-Owner protection are not implemented. |
| OPEN-005 | Review rating scale | Spec FR09: 3 ratings; design-system: 4 ratings. Decide before KIKO-016. |
| OPEN-006 | Primary UI font | design-system proposes Inter; system fonts kept for now (DEC-008). |
